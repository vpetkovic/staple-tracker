Documentation

Use Staple programmatically

Staple exposes the same task model through MCP and the command line. MCP is the main interface for agents. The CLI is useful for people, scripts, and CI.

Quickstart

Staple needs Node.js 22.5 or newer. Nothing else. One command sets a repository up and opens the local UI; one more wires an agent harness.

npx staple-cli   # onboard + open the UI
claude mcp add staple -e STAPLE_AGENT=claude -- npx -y staple-cli mcp

The first run asks a couple of questions; npx staple-cli --yes accepts the defaults, and in CI it performs the setup without starting the UI server. For a global workspace, use staple init --global <slug>. Set STAPLE_HOME to relocate the local hub. To put staple on your PATH permanently, run npx staple-cli install --yes.

Workspace model

A repository workspace lives at .staple/staple.db. Staple finds it by walking up from the current directory; a legacy .tasks/tasks.db is still found, and staple migrate --yes moves it. Global workspaces live under ~/.staple/workspaces/. The hub at ~/.staple/hub.db registers both kinds.

Each workspace receives a unique prefix, so references such as STA-12 remain clear across repositories. Cross-workspace dependency edges live in the hub. If a referenced workspace is missing on the current machine, Staple treats that blocker as unresolved.

VariablePurpose
STAPLE_DBUse an explicit workspace database.
STAPLE_WSSelect a hub workspace by slug or prefix.
STAPLE_AGENTSet the default agent identity.
STAPLE_HOMEMove the hub and global workspace directory.

Connect an MCP client

Register the stdio server with the agent name in its environment. This Claude Code example starts a fresh Staple process when the client connects.

claude mcp add staple -e STAPLE_AGENT=claude -- npx -y staple-cli mcp

Any MCP client can launch npx -y staple-cli mcp the same way. Writes require an identity: set STAPLE_AGENT in the server environment or pass actor per call.

The recommended agent loop

  1. Call inbox at session start.
  2. Call checkout_task. If it returns conflict, pick a different task. Do not retry that claim.
  3. Call get_task for ancestry, acceptance criteria, relations, comments, and documents.
  4. Write the plan with put_document, then add progress through add_comment.
  5. Finish with update_task and status done.
  6. Call events_since with the last sequence number to discover work that became ready.
A task can enter in_progress only when it has an assignee and no unresolved blockers. Staple enforces that rule in every interface.

CLI and machine-readable output

The CLI covers initialization, task creation and flow, comments, dependencies, documents, events, hub operations, terminal views, and the local web UI. Run staple help for the full option list.

staple new "Add retry policy" --assignee codex -p high
staple start STA-12 --agent codex
staple block STA-12 --owner user --action "choose timeout"
staple blocked-by STA-12 STA-9,STA-10
staple done STA-12 -m "Added policy and tests"

Add --json to task commands for full store objects with ISO-8601 timestamps. events --json writes NDJSON, one event per line.

Revisioned documents

Documents are keyed records attached to a task. Common keys include plan and notes. Every write creates a revision. Pass base_revision through MCP or --base through the CLI to prevent a stale writer from overwriting newer work.

staple doc STA-12 plan --put plan.md
staple doc STA-12 plan
staple doc STA-12 plan --put revised.md --base 1
staple doc STA-12 plan --revisions

Dependencies and task trees

set_blocked_by replaces the full blocker set. Staple rejects self-links and cycles. When all blockers resolve, it emits blockers_resolved. Parent tasks can also block on their children, and the last completed child emits children_complete.

Use cross_link or staple link for dependencies between repositories. Local and cross-workspace edges appear together in hub graph mode.

Event cursors

Events have increasing sequence numbers. Save the last number an agent saw, then pass it back on the next poll. Completion events are level-triggered and deduplicated, so a task that becomes blocked again can wake again after its new blockers resolve.

Errors and retries

All programmatic errors include code, message, optional detail, and retryable. Only revision_conflict is retryable. Reread the document, merge, and submit against the current revision.

ExitCodeMeaning
2validationInput or state rule failed.
3not_foundThe reference does not exist.
4conflictAnother agent holds the task, or checkout is not allowed.
5duplicateA guarded duplicate exists.
6cycleThe dependency would create a cycle.
7revision_conflictThe document changed after the supplied base.

Local UI

Start staple open for one workspace or staple open --hub for every available workspace (staple ui is a compatibility alias). The page includes a dependency-aware inbox, seven-column board, task tree, dependency graph, document viewer, comments, relations, and common task actions. It binds to 127.0.0.1 and runs only while the command is active.

Prototype limits

  • There is no remote sync engine yet. GitHub Issues and ClickUp adapters are planned.
  • Combined cycles that span three workspace files are not detected. Each local graph and the hub graph guard their own edges.
  • Search uses SQL LIKE, and labels live in a JSON column.
  • SQLite coordinates processes on one machine. It is not intended for shared NFS mounts or multi-host writes.

Local-first coordination

Give your agents work they can trust.

Staple replaces loose plan files and chat-only handoffs with a small task system that lives beside your code. Agents can claim work safely, follow dependencies, and leave a readable history without a hosted service.

Why Staple

Small enough to carry. Strict where it counts.

Coding agents fail in boring ways. Two agents pick the same task. A blocked task starts too early. A plan gets overwritten. Staple handles those races in SQLite, close to the work, with errors agents can act on.

01

Atomic checkout

One agent wins the claim. Every other agent gets a typed conflict and moves to a different task. The same agent can reclaim after a crash.

02

Dependency-aware inbox

The inbox puts workable tasks first and names every unresolved blocker. Cycle detection stops impossible graphs before they land.

03

Revisioned plans

Store plans and notes on the task. Optimistic concurrency catches stale edits, while the revision history keeps old decisions recoverable.

04

Workspace hub

Each repository keeps its own database. The local hub gives every workspace a unique prefix and connects dependencies across repositories.

05

Events agents can poll

Completion emits events when blockers clear or the last child finishes. Agents resume from a sequence cursor instead of rereading everything.

06

One model, three interfaces

MCP is the agent interface. The CLI mirrors it for people and CI. The local UI turns the same data into an inbox, board, tree, dependency graph, and task detail.

07

Safe retries

Idempotency keys replay task creation without duplicates. Open sibling titles and machine-origin records have duplicate guards.

08

Machine-readable failures

JSON errors have stable codes, details, and a retryable flag. CLI exit codes let scripts branch without scraping prose.

09

Local by default

State stays in a copyable SQLite file. There is no account, cloud database, background service, or native runtime dependency.

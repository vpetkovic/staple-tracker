# Why staple

This page explains why staple exists and where it fits next to the tracker your
team already uses.

## What this page will cover

- The problem: implementation plans kept as piles of Markdown files that depend
  on each other and fall apart when an agent session ends.
- Tickets as first-class records that give an agent the full context it needs.
- Handoff: parking a task and resuming it in another session or with another agent.
- Local-first: one database per repository, with no network call on the agent's path.
- A human in the loop without babysitting.
- staple as the execution layer next to Linear, GitHub or ClickUp, and the planned
  integrations that keep the two in sync.

Until this page is written, [Install and first workspace](getting-started.md)
shows staple at work.
